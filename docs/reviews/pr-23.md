### P2-1: Accepts a CSV file marked incomplete

Status: open.

Open at: `13bdbb1c6cd187e867b644be9afaf5c4ec95db2c`.

File: `IronAbsolution.Tools/FrameCapture/FrameTimeCsv.cs:83-87`.

Trigger: The closing metadata contains `[HasHeaderRowAtEnd],0`, with otherwise valid rows and settings.

Expected: The reader accepts only a completed profiler file (D-137, T-2).

Actual: The reader checks only that the completion key exists. It accepts the value `0`, then the command can pass the capture.

Consequence: An incomplete profiler file can provide a passing value of M-3.

Evidence: The committed engine capture writes `[HasHeaderRowAtEnd],1`. The reader discards that value and checks only `ContainsKey`.

Correction: Require the completion marker value `1`; report the file path and invalid value otherwise.

Regression check: Add a complete fixture with marker value `0`. `FrameTimeCsv.Read` must fail with the file path and marker value.

### P2-2: Does not require the fixed set of four views

Status: open.

Open at: `13bdbb1c6cd187e867b644be9afaf5c4ec95db2c`.

File: `IronAbsolution.Tools/FrameCapture/FrameCaptureRules.cs:185-212`.

Trigger: The gym has fewer or more than the four views defined by the content script.

Expected: The capture uses the fixed set of four views in the gym (D-137).

Actual: The rule does not check `IronAbsolution.ViewCount`. It reports success even when that key is absent or its value differs from four.

Consequence: A changed capture scene can produce a passing M-3 value from a different set of views.

Evidence: The content script defines four views. The C++ subsystem records their count. The command omits that metadata key from its required settings.

Correction: Require a view count of four in the capture settings check.

Regression check: Test metadata with a missing count and counts of three and five. Each capture must fail the settings check. A count of four must pass.
