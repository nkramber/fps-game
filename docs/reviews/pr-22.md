## Findings

### P2-1: Zero world gravity leaves a partial tuning

Status: open.

Open at: `e1d5667ccd6e7e5ac3534390dcb2beea1b1a7dac`.

File: `Game/Source/IronAbsolution/Private/IronPlayerCharacter.cpp:55-70`.

Trigger: Call `ApplyMovementTuning` with a valid tuning in a world with zero gravity.

Expected: A failed application leaves the character unchanged. The function contract says this, and T-2 requires an error with context.

Actual: The function writes speed, acceleration, braking, friction, gravity scale, air control, step height, and slope before it checks world gravity. It then reports an error and returns false without setting jump speed, eye height, or field of view.

Consequence: The character keeps part of the rejected tuning, which can produce inconsistent movement and camera values.

Evidence: The full control path in `ApplyMovementTuning` writes the movement fields at lines 55 to 63, then returns false at the zero-gravity check at lines 67 to 70. The existing invalid-tuning test checks only a range failure before those writes.

Correction: Validate the resulting gravity before writing any movement or camera field, or restore all fields on failure.

Regression check: Add an automation test that sets world gravity to zero, calls `ApplyMovementTuning`, expects false and an error line, and verifies each movement and camera field stays unchanged.

### P2-2: NaN tuning values pass range validation

Status: open.

Open at: `e1d5667ccd6e7e5ac3534390dcb2beea1b1a7dac`.

File: `Game/Source/IronAbsolution/Private/IronMovementTuning.cpp:37-43`.

Trigger: A tuning asset contains NaN for one or more float values.

Expected: `FindInvalidValues` rejects each value outside its stated range, and T-2 treats invalid tuning as an error.

Actual: The comparisons `Value < Min` and `Value > Max` both return false for NaN, so the method reports no error and `ApplyMovementTuning` uses the value.

Consequence: A malformed asset can place NaN in the movement component or camera and can corrupt player movement or view calculations without an error.

Evidence: The range loop only compares each value with its minimum and maximum. It has no finite-value check.

Correction: Reject each non-finite value before the range comparisons and include the property name and asset path in the error.

Regression check: Add a tuning automation test with a NaN field. Expect one contextual error for that field and verify the character rejects the tuning without changing its state.
