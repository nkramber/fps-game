## Findings

### P2-1: A non-finite door offset corrupts its transform

Status: open.

Open at: `6f9f91b7dafa4509196c2bf836d0a22ab181ceca`.

File: `Game/Source/IronAbsolution/Private/IronDoor.cpp:27-34`.

Trigger: A placed door has a non-finite component in `OpenOffset`, such as NaN or infinity, and the player uses the door or its switch.

Expected: The door reports invalid data and keeps its state and transform unchanged (T-2).

Actual: `IsNearlyZero` returns false for a non-finite vector. `Toggle` flips `bIsOpen` and writes the invalid vector to the panel without an error.

Consequence: Invalid content silently corrupts the panel transform and reports the door as open.

Evidence: `AIronDoor::Toggle` checks only whether the offset is nearly zero before it updates the state and transform. `Interact.Errors` checks the zero case alone (`Game/Source/IronAbsolution/Private/Tests/InteractTest.cpp:210-215`).

Correction: Reject any non-finite offset before changing the door state. Include the door path and invalid offset in the error.

Regression check: Extend `IronAbsolution.Player.Interact.Errors` with NaN and infinity offsets. Each use must log an error, keep the door closed, and leave the panel at its last valid location.
