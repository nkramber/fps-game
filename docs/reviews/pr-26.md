## Findings

### P2-1: Positive infinity passes the flash and HUD checks

Status: open.

Open at: `3becf704562b81a2a497e3b5738391ad8bb8333c`.

File: `Game/Source/IronAbsolution/Private/IronHitFlash.cpp:35`, `Game/Source/IronAbsolution/Private/IronHUD.cpp:49`.

Trigger: A Blueprint sets `Lifetime` or `HitMarkerSeconds` to positive infinity.

Expected: Each non-finite tuning value reports an error with its actor path, and the flash lifetime and hit-marker duration stay finite (T-2, D-29, D-154).

Actual: Each check only rejects a value that is not greater than zero. Positive infinity passes. The flash then sets an infinite lifespan and its brightness stays at 1. The hit marker remains shown because every finite age is below an infinite duration.

Consequence: Each hit can leave a flash actor in the world, and the HUD can keep showing the hit marker without an expiry.

Evidence: `!(Lifetime > 0.0f)` and `!(Case.Value > 0.0f)` both accept positive infinity. `AIronHitFlash::BeginPlay` passes that lifetime to `SetLifeSpan`, and `AIronHUD::DrawHUD` passes the duration to `IsHitMarkerShown`.

Correction: Reject non-finite values before the positive range checks. Include the actor path and the invalid value in each error.

Regression check: Add automation cases with positive infinity for `Lifetime` and `HitMarkerSeconds`. Each case must report an error, and the old code must fail each assertion.
